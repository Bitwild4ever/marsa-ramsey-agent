二次开发 Moonshine：把精确计算内核接成数学 agent 的一等工具

背景：老师给了自研的数学研究 agent「Moonshine」，要求借鉴以加速框架研发。
研读后确认了一个真实缺口，并把它补上了。

关键判断：Moonshine 原生的 verify_correctness_* 是 LLM 评审
----------------------------------------------------------
它审查的是"证明过程"里有没有计算错误、假设误用、逻辑漏洞 —— 对待数学证明合理。
但对**计算性断言**（如"这个 43 顶点的图不含 K5"）LLM 无法判定：它只能评论，
不能枚举团。这类断言必须由**精确计算**决定，且需要一条与搜索器**独立实现**的
验证路径，否则搜索器算错时会一起错。

因此本次二次开发的实质：补上框架在**构造性组合问题**上的验证缺口。

新增内容（全部在 ramsey-pack/，不重新发布 Moonshine 源码）
---------------------------------------------------------
- tools/ramsey_tools.py       四个确定性工具（不调用 LLM）
  * ramsey_verify_construction  精确独立判定构造是否合法（判定：verified/refuted）
  * ramsey_enumerate_family     穷举循环图族并给出判定（exists/none_exist）
  * ramsey_search               固定墙钟预算的搜索，成功必经独立复核
  * ramsey_violations           精确违反度计数
- tools/definitions/*.md      四个工具定义（Usage Hint 写成路由条件）
- skills/ramsey-construction-search/SKILL.md
                              教 agent 何时用哪个工具，并严格区分
                              「已证明 / 部分进展 / 无定论」三种状态，
                              并明确禁止把构造断言送去 LLM 评审
- install.py                  幂等安装器（复制 + 给 registry.py 打注册补丁）
- test_ramsey_tools.py        端到端自检（走 ToolRegistry 真实派发）
- README.md                   说明为何必须改源码、与原生验证的分工

唯一改动 Moonshine 源码之处
--------------------------
tools/registry.py 的 _handler_map 是硬编码的，运行时工具定义无法引入新的
Python 实现，故必须打补丁。改动为纯新增约 40 行，带 try/except 保护：
marsa 未安装时 Moonshine 其余功能照常工作。原文件备份为 registry.py.orig。

验证结果（端到端跑通）
---------------------
- 4 个工具在 `moonshine tools` 中正确列出
- ramsey_search@34 -> solved（0.85s, 476 步），独立验证器复核通过 -> R(5,5) > 34
- ramsey_enumerate_family@38 -> exists（18 个解 / 524,288 个成员，穷举）
- 反向交叉校验：ramsey_enumerate_family@46 -> none_exist，
  与已证明的 R(5,5) <= 46 一致 —— 用已知定理佐证内核正确性
- 安装器幂等（重复运行不会重复打补丁）

配套：pyproject.toml 让 marsa 引擎可被 pip 安装为包（Moonshine 需能 import 它）。
.gitignore 排除 Moonshine 源码与运行时目录（第三方与生成物不入库）。

一处需要说明的操作失误：初始化 Moonshine 运行时目录时，因误用 PowerShell
只读自动变量 $home，把它建到了用户主目录 C:\Users\26319。已逐项核验时间戳
（全部晚于 init 时刻）后完整清除，主目录已复原，随后正确地建在
D:\myagent\moonshine-home。
