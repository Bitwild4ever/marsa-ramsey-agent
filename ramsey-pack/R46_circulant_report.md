## 4. 为什么这些 `none_exist` 可信（防漏判的独立交叉校验）

否定结论唯一的风险是"枚举器自己的判定函数漏判"。因此把判定拆成三条独立实现，
在**整个空间**上对比"合法解个数"：

| 路径 | 实现 | 算法/数据结构 |
|---|---|---|
| A | `marsa.symmetric.FastChecker` | 预计算"含 0 的 s/t-子集"偏移掩码，判 `(S&M)==M` / `==0` |
| D | `_r46_direct.DirectChecker`（本次新写） | 枚举**全部** C(n,k) 个子集（不假设平移对称），去重后按位测试 |
| C | `marsa.verifier.verify` | 显式布尔邻接矩阵 + `itertools` 子集枚举（即 CLI `verify`） |

全空间对比结果（A 与 D 对所有 n；C 为独立验证器，仅对小空间做了全空间全扫）：

| n | A 计数 | D 计数 | A==D | C 全空间计数(D 用) | A==C | 样本数(A/C/D 逐条) | 样本分歧 |
|---|---|---|---|---|---|---|---|
| 36 | 0 | 0 | 是 | 0 | 是 | 337 | 0 |
| 37 | 0 | 0 | 是 | 0 | 是 | 340 | 0 |
| 38 | 0 | 0 | 是 | （空间过大，仅样本） | — | 338 | 0 |
| 39 | 0 | 0 | 是 | （空间过大，仅样本） | — | 339 | 0 |
| 40 | 0 | 0 | 是 | （空间过大，仅样本） | — | 341 | 0 |
| 41 | 0 | 0 | 是 | （空间过大，仅样本） | — | 342 | 0 |

- 样本集刻意包含边界与病态输入：全 0 串、全 1 串、`1`、全部单比特、随机串、
  以及随机串的 AND / OR 组合。
- **n = 36 与 37 是三重全空间确认**：A、D、C 三条路径各扫完整个 262,144 成员空间，
  都得到 0 个合法解。
- n = 38…41 的独立验证器 C 因单次调用过慢（实测 `Coloring.cost` 约 132–350 ms/次，
  全空间需数十小时）只在样本上参与，全空间由 A 与 D 双路完成。这一点如实标注。

### 正向对照（证明工具链不是"永远回答无解"）

同一段代码路径在 `n = 30, 31, 33` 上**找得到**合法解，并由独立验证器
`verify --s 4 --t 6` 返回 `status: verified, violations: 0`。因此
`n = 36…41` 的 `none_exist` 不是判定函数恒为假造成的假象。
（另注：`n = 32, 34, 35` 亦为 `none_exist`。循环图族的解**不随 n 单调**——
删点会破坏循环结构——所以不能从 `n=33` 有解推出 `n=34` 有解。）
