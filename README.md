## 它是什么

不是"给一个算法套个 agent 的壳"，而是**一个能自己决定用什么工具、工具不够用时会自己造、
并且在证据不足时拒绝下结论的 agent**。

数学问题在这里的角色是**检验水平的工具**，不是目的本身。

具体到实现：它跑在开源 agent 框架 **Moonshine**（课程老师的项目）之上，
我们做的是**二次开发**——补齐它缺失的确定性计算层，并给它一套专精的领域人格与方法论技能。

## 它凭什么算 agent

三条硬证据，都有可追溯的运行记录：

### 1. 工具不够用时，它自己造

发现框架自带的族枚举工具只支持循环图（circulant），它**自己写了一个非循环 Cayley 群枚举器**，
还配了分片、可续跑、断点接续的驱动脚本。第一版因每个掩码都重建邻接矩阵而超时，
它自己记录根因（比引擎慢两三个数量级）并改成只构造 row-0 再平移。

> 见 [agent-runs/ramsey_agent_run/](agent-runs/ramsey_agent_run/) 里的 `cayley_exhaust.py`、`cayley_shard.py`

### 2. 造完工具，它先用已知答案验它

在信任自己的代码之前，它设了 **5 个锚点**（`n=38` 应有解；`43/44/45/46` 应无解），
逐一复现引擎的判定，**全过才承认自己的枚举器可用**。

### 3. 证据不足时，它拒绝下结论；发现错时，它主动撤回

- 对 23.8% 的部分扫描，它明说：**"这不是判定，不是排除"**。
- 它先前论证过"强正则图型构造不可能"，后来发现论证依赖一个**无效的必要条件**（λ ≤ 3），
  于是**主动撤回**并标注"不得引用为已排除"。

它自己从这些错误里总结出一条规律：

> **"六处错误中五处出在间接推理（必要条件、公式记忆、计数转述）；
> 而经枚举 + 直接验证得出的四条结论从未出错。"**

这条元认识，比任何一个具体的数学结论都更有价值——它直接决定了我们该在什么环节信任它。

## 架构

```
┌─────────────────────────────────────────────────────────┐
│  Moonshine 运行时（老师的开源框架，未改动核心逻辑）        │
│  研究循环 / 验证门禁 / 类型化日志 / 记忆 / 报告生成        │
└───────────────────────┬─────────────────────────────────┘
                        │ 我们补的是这一层 ↓
┌───────────────────────┴─────────────────────────────────┐
│  领域包 ramsey-pack/                                     │
│  ├─ 5 个确定性工具（不调用 LLM）                          │
│  ├─ 4 份技能（渐进式披露的方法论）                         │
│  └─ 1 个 agent 人格                                      │
└───────────────────────┬─────────────────────────────────┘
                        │
┌───────────────────────┴─────────────────────────────────┐
│  计算内核 marsa/（位掩码增量代价 + 独立验证器）            │
└─────────────────────────────────────────────────────────┘
```

**为什么必须补这一层**：Moonshine 原生的验证是 **LLM 评审**，它审的是"证明过程"，
**无法判定"某个具体图不含 K₅"这类计算性断言**。把计算断言送进 LLM 评审，
只会得到一个自信但无意义的回答。所以我们补了确定性工具，并让验证器当唯一仲裁者。

### 五个工具

| 工具 | 作用 | 关键性质 |
|---|---|---|
| `ramsey_verify_construction` | 精确验证一份构造 | **与搜索器独立实现**，是唯一仲裁者 |
| `ramsey_enumerate_family` | 穷举对称族 | **判定性**：能给出 `none_exist` 这种关闭性结论 |
| `ramsey_search` | 固定墙钟预算搜索 | 成功必经独立复核；失败不代表不存在 |
| `ramsey_violations` | 精确统计违反度 | 廉价、精确 |
| `ramsey_compare` | 多算子公平比较 | **统计纪律自检**：给出 `solved` / `clear_winner` / `inconclusive` 判定 |

> `ramsey_compare` 是后来加的重点。因为真实发生过一次：某算子在 `n=44` 上均值略低，
> 被写成"最好"，而独立复算显示两者**落在种子噪声内**。与其在文档里再叮嘱一次"要诚实"，
> 不如把这条判断**放进工具的返回值**——比较的那一刻由代码给出 verdict，事后无法合理化掉。
> 这对应课程材料里的原则：**约束优先于指导**。

## 目前的真实水平

### 做到了

- **39 项测试全绿**（6 个套件：核心 / 记忆 / 规划器 / 选择器 / 对称族 / 统计纪律）
- **两次真实自主运行**：
  - 首轮 10 轮迭代、**86 次工具调用**、500+ 行研究日志
  - 稳定性测试 15 轮、**38 次工具调用**、56 条日志、**无死循环**
- **交叉验证**：两条**独立实现**的判定路径在 9 个用例上全空间一致
- **判定性结论**：循环图族在 `n ∈ {39, 42, 43, 44, 45, 46}` 上无解；
  非循环 Cayley 的 `Z_2×Z_22` 在 n=44 上已扫 23.8%，无解（**但不构成排除**）

### 没做到

| 没做到 | 诚实的原因 |
|---|---|
| **`R(5,5)` 的空隙一格没动** | `43 ≤ R(5,5) ≤ 46` 依然成立。产出全在 agent 侧 |
| 不做上界 | 上界是证明问题；它只有构造工具 |
| 巨大族不可枚举 | 非循环 Cayley 在 n=44 是 2⁴³，是算力问题不是方法问题 |
| 统计显著性 | 它自己判断不了，靠 `ramsey_compare` 兜住 |
| 数小时以上的无人值守 | 目前只验证到 15 轮 |

### 用一句话定位

**一个谨慎、会自验、但间接推理不可靠的初级研究者。**

在"能直接验证"的判断上接近可用；在"需要间接推理"的判断上必须外部复核。
