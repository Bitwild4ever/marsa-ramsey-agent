# DSH 衍生子智能体

把本项目的领域方法论固化成一个**可复用的子智能体人格**，跑在 DSH 的模型通道上。

## 为什么走这条路（先说清技术事实）

本来最直接的方案是给 Moonshine 配一个模型接口。我核查了这台机器：

| 检查项 | 结果 |
|---|---|
| DSH profile 里配置的模型 | ✅ `deepseek-official` / `deepseek-flash`（见 `cordis.patch.yml`） |
| DSH 是否暴露 OpenAI 兼容端点 | ❌ `/v1/models` → 404，`/api/*` → 401 |
| 是否存在本地模型网关端口 | ❌ 遍历监听端口，只有 DSH 的 Web GUI（19387）等，无模型服务 |
| 环境里是否有 API key | ❌ 无 |

**结论：DSH 的模型访问在 harness 进程内部，没有对外暴露成通用 API，
所以"让 Moonshine 把我当模型后端调用"这条具体接线是做不到的。**

但**你想法里有用的那一半完全成立**：DSH 本身就是一个 agent harness
（工具调用、技能渐进式披露、子智能体、后台作业、长期目标），
它缺的只是"领域人格 + 领域工具"。而这两样我们现在都有了。

所以：**衍生子智能体 = DSH 子智能体 + 本项目的 MARSA 人格 + ramsey-pack 工具层。**
不需要任何额外 key。

## 怎么用

### 方式一：直接派发（最简）

```
subagent(
  description="...",
  prompt="你是 MARSA 衍生子智能体。第一步：完整读取
          D:\\myagent\\dsh-agent\\PERSONA.md，严格按其中的人格、
          证据标准与报告纪律工作。\n\n## 任务\n<你的具体任务>"
)
```

要点：**第一句让它先读 `PERSONA.md`**。人格文件里已经写好了工具用法、
已知边界、报告纪律与不可重试的路线，不必塞进 prompt。

### 方式二：先读人格再手工派活

打开 `PERSONA.md` 看一眼它的性格是否符合你这次的任务；
不合适就在 prompt 里显式覆盖（prompt 优先级高于人格文件）。

## 已经验证过：它真的能干活

我用派发方式给它一个**我们此前从未做过的真实任务**：

> 对 `R(4,6)` 的循环图族做完整刻画，覆盖 `n = 36…41`。

它的产出（见 [runs_r46/](runs_r46/) 与
[R46_circulant_report.md](R46_circulant_report.md)）：

| n | 判定 | 合法解 | 空间 |
|---|---|---|---|
| 36 | `none_exist` | 0 | 262,144 |
| 37 | `none_exist` | 0 | 262,144 |
| 38 | `none_exist` | 0 | 524,288 |
| 39 | `none_exist` | 0 | 524,288 |
| 40 | `none_exist` | 0 | 1,048,576 |
| 41 | `none_exist` | 0 | 1,048,576 |

合计 **3,670,016** 个成员全部查完。结论：**循环图族无法改进 `R(4,6)` 的下界**
（`n = 36` 无解，所以拿不到 `R(4,6) >= 36`）。

### 它做得比我预期好的地方

1. **它自己写了第二条独立实现**（现在升格为 [direct_checker.py](direct_checker.py)）。
   我的 `FastChecker` 假定平移对称、只枚举含顶点 0 的子集；它**不假设对称**，
   枚举全部 `C(n,k)` 个子集，并用不同形式的位测试。三条实现差异，
   任何一处写错都会让合法解计数不同。
2. **它加了正向对照**：在 `n = 30, 31, 33` 上确认**找得到解**，
   以此证明"无解"不是判定函数恒假的假象。
3. **它发现了我 CLI 的一个真 bug**：`--quiet` 分支在 GBK 代码页下
   打印 `⇒` 会抛 `UnicodeEncodeError` 导致整个命令失败。已修复
   （启动时把标准流切到 UTF-8），并已验证。
4. **它主动指出非单调性**：循环图族在 `n = 33` 有解而 `34, 35` 无解 ——
   这个性质我在技能文件里写过，它真的用上了。

我也**独立复算**了它的三项关键结论（(4,6)@36 无解、n=30 正向对照通过验证、
33/34/35 非单调），与它一致。

## 诚实边界

- **这条路的定位是"让方法论可运行、可演示"**，不是替代 Moonshine。
  Moonshine 仍是老师框架的正统交付物，它一旦拿到任意一个 OpenAI 兼容的 key
  就能用我们的 pack 跑自主研究。两者互补。
- **子智能体是会话内派发的**，不是一个可以脱离 DSH 独立部署的常驻服务。
  想要常驻，需要做成 DSH 的 bundle 包（见 profile 的 `cordis.patch.yml`
  与 `package.json` 的 `bundles` 机制），那是另一档工作量。
- **视觉版面、长时程自主运行**这两项我仍未验证：前者需要浏览器，
  后者需要在 DSH 之外真实跑一轮（即 Moonshine + key）。
