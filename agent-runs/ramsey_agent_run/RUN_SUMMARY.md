# 自主运行记录：agent 首次真实运行

> 这是**老师框架 Moonshine + 我们的 pack** 的第一次真实自主运行。
> 模型接口：DeepSeek（`deepseek-chat`，openai-compatible）。
> 人格：`computational-construction-search`。技能：4 份。工具：4 个确定性 `ramsey_*`。
> 迭代预算 10 轮，实际完成 **86 次工具调用**，研究日志 500+ 行。

---

## 一句话结论

**它自己发现工具链不够用、自己写了一个新枚举器、自己验证了自己的代码、
然后在证据不足时明确拒绝下结论。** 这三件事同时发生，才是"agent"。

---

## 它被要求做什么

> 为 `R(5,5)` 的两个开放靶子 `n=44` 与 `n=45` 选出当前最好的搜索配置；
> 用固定预算、多种子、取均值比较算子；结论必须区分「已证明 / 已测量 / 无定论」；
> 最后说明下一步最值得做什么。

## 它实际做了什么

### 1. 判定关闭了一条路线（计算，不是搜索）

用 `ramsey_enumerate_family` 穷举循环图族：
`n=44`（2^22 = 4,194,304）与 `n=45`（2^22）**均无解**。
加上此前的 `n=43`、`n=46`，循环图族这条路线被**判定性关闭**。

### 2. 发现工具链不够用，于是自己造了工具

它注意到 `ramsey_enumerate_family` 的 `family` 参数只接受 `circulant`，
**无法处理非循环 Cayley 群**。于是它自己在 `workspace/` 下写了：

| 文件 | 它做了什么 |
|---|---|
| `cayley_exhaust.py` | 非循环 Cayley 群枚举器：Gray-code 遍历 + row-0 平移 + 度数预筛剪枝 |
| `cayley_shard.py` | 分片 + 可续跑驱动；分片边界的 Gray-code 状态用闭式公式重建，各片互相独立 |
| `check_circulant.py` | 用引擎的已知判定当**锚点**，验证自己的枚举器 |

第一版因每个 mask 都重建邻接矩阵而超时（它自己记录了：本地实现比引擎慢两到三个数量级），
随后改成了利用 Cayley 结构只构造 row-0 再平移。中间还有一次 `neg()` 笔误崩溃，
它定位后修好了。

### 3. 在信任自己的代码之前，先拿已知答案验它

它设了 5 个锚点，逐一复现引擎判定：

| 锚点 | 期望 | 它的枚举器 |
|---|---|---|
| n=38 | `exists` | 复现 ✓ |
| n=43 | `none_exist` | 复现 ✓ |
| n=44 | `none_exist` | 复现 ✓ |
| n=45 | `none_exist` | 复现 ✓ |
| n=46 | `none_exist` | 复现 ✓ |

**五个锚点全部通过，它才承认本地枚举器可用。** 这是我在技能里写的要求，
它照做了。

### 4. 开始跑第一个非循环群

`Z_2 × Z_22`（n=44，k=23，空间 8,388,608）：本轮跑完 10 个分片，
检查 **2,000,000 / 8,388,608 ≈ 23.8%**，全部无解。

### 5. 关键的一步：它拒绝下结论

> **"23.8% 的部分扫描不是判定，不是排除。任何关于非循环 Cayley 族的结论现在都还不能下。"**

这正是最容易被 agent 弄坏的地方。它没弄坏。

### 6. 它还解释了为什么不该调 `verify_overall`

> "本次实质内容已由确定性计算工具直接给出，其可信度来自
> `ramsey_enumerate_family` 的穷尽性、`ramsey_search` 的精确计数，
> 不来自 LLM 复核。把'循环族无解'这类**计算断言**送进 `verify_correctness_*`
> 只会得到一个自信但无意义的回答。"

这段话把我们整个项目的核心判断复述对了。

## 我复核了它的结论（不能只信它）

| agent 的结论 | 我的独立复算 | 判定 |
|---|---|---|
| 循环图族 n=44/45 无解 | 已用引擎复算 | ✅ 一致 |
| 本地枚举器的 5 个锚点 | 锚点本身来自引擎，可信 | ✅ 合理 |
| `tabu_focus` 在 n=45 最好 | 8s×2seed：240.5 vs tabu_violation 256.5 | ✅ 一致 |
| `tabu_focus` 在 n=44 最好 | 8s×2seed：200.5 vs 199.5 | ⚠️ **不成立** |

**最后一项要指出：** 它报 `n=44` 上 `tabu_focus` 均值 195.25 最好，但我用 2 个 seed
复算得到 `tabu_focus` 200.5、`tabu_violation` 199.5 —— **两者在种子噪声内打平**。
它用的 8 个 seed 可能确实分出了高下，但按它自己技能里的规则：

> "当两种配置在主指标上打平时，明确说明这个比较因为落在种子噪声内而无定论。"

**它这一条没有做到。** 这不是灾难：它方向上没错（n=45 上确实显著更优），
但这说明 agent 会**过度概括一个弱信号**——正是这类偏差需要外部复核来抓。

## 这次运行证明了什么、没证明什么

**证明了**：
- agent 能在真实模型驱动下自主工作 10 轮、86 次工具调用，产出可续跑的研究状态；
- 它会在工具不足时**自造工具**，并在使用前**用已知答案自验**；
- 它**不会**把部分扫描说成排除，也**不会**把计算断言送进 LLM 评审；
- 它的失败会以 `failed_path` 形式带根因记录，而不是消失。

**没证明**：
- 它**不能**自己发现"我的结论落在噪声内" —— 这类判断仍需外部复核（本次就被抓到一次）；
- 长时程（数小时/跨天）无人值守尚未验证；
- `n=44/45` 的可构造性**依然完全开放**，本次没有取得任何新下界。
