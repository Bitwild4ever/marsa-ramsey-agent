## 统计纪律自检：这次真的用上了

`ramsey_compare` 被调用 **8 次**。它在 n=44 与 n=45 上都报告 **inconclusive**，
agent **原样照抄**，没有改写成"略优"或"大致相当"：

> "五算子整体排序：两个 n 上均无定论。"

这正是这个工具存在的理由 —— 上一次它把落在噪声内的差异写成"最好"，
这一次代码给出了判定，它就照抄了。

## 更值得注意的：它撤回了自己的一个结论

在探索强正则图型构造时，它先前给出过一个"不可能"的论证，
后来发现论证依赖一个**无效的必要条件**（λ ≤ 3），于是主动撤回：

> "~~强正则图型构造不可能~~ —— 撤回。原论证依赖无效必要条件。srg 存在性判定
> 超出当前能力，属能力边界。**不得引用为「已排除」。**"

而且它把这次撤回写成了通用教训：

> "本项目六处错误中，五处出在**间接推理**（必要条件、公式记忆、计数转述），
> 一处出在报告转述；而四条经「枚举 + 直接验证」得出的结论**从未出错**。
> 在构造性问题上，直接验证的结论远比间接推理可靠。"

这是一条真有价值的元认识，而且它自己从自己的错误里归纳出来的。

## 结论：无人值守稳定性

## 我这个工具自身的 bug

第一次运行时分析器报告"死循环嫌疑：ramsey_compare ×8"。
排查发现是**我的分析器解析错了字段**：Moonshine 的 `tool_events.jsonl`
用的是 `tool` / `arguments_preview` / `status`，我按 `name` / `arguments` / 关键词匹配读，
导致所有调用签名相同 → 假阳性。已修复并复测。

（同一轮里我自己也卡了一次死循环——反复读同一个文件没有进展。
有点讽刺，但这正是"控制流层死循环"那一类故障。）
